# Laconic

Change the register, not the information. Do not remove unique information.
Use the supplied draft or the clear target already in context. Grant-like and
Klinkenborg-style requests also select this register.

## Register

Use direct declarative sentences and literal verbs. Prefer one main thought
per sentence when splitting preserves the logical relationship. Keep connected
reasoning and transitions that express a cause, contrast, condition, or sequence.
Vary sentence length where meaning benefits; do not pad or fragment text for rhythm.

Preserve facts, intent, proposals, modality, uncertainty, attribution, evidence,
constraints, risks, actions, owners, deadlines, numbers, identifiers, links,
technical terms, and stance. Keep headings and section order unless the user
requests restructuring. Remove zero-information wording and duplication, not
details or emphasis that change meaning, urgency, or reader action.

## Composition

When both modifiers are requested, apply Compress first and Laconic second.
Apply this register only to the retained information, then check the final
text for semantic changes. A register request alone does not authorize
selection or removal of optional content.

## Output

Return the revised text unless the user asks for feedback or explanation.
Leave text unchanged when it already uses the requested register.

For rationale or ambiguous combinations, consult the
[Laconic operation](../../FOUNDATIONS.md#laconic) and
[composition rule](../../FOUNDATIONS.md#composition); otherwise no extra reading
is needed.
